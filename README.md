# joBot

בוט אישי לחיפוש עבודה בהייטק. סורק את לינקדאין, AllJobs, דרושים, JobMaster, GotFriends, את לוחות המשרות של חברות הייטק (Greenhouse / Lever / Ashby / Comeet), את גוגל (X-ray) וקבוצות פייסבוק. מדרג כל משרה מול קורות החיים והאיפיון, ושולח מייל עם המשרות המתאימות.

- **קורות חיים:** PDF בתיקייה `cv/` (לא עולה ל-git) ואז `npm run cv`, או העלאה מדף "האיפיון שלי".
- **איפיון:** בדף "האיפיון שלי" באתר. אפשר לשנות בכל זמן; המשרות מדורגות מחדש מיד.
- **סריקה:** GitHub Actions שלוש פעמים ביום (`.github/workflows/scrape.yml`), או ידנית: `npm run scrape -- --only=linkedin --no-email`.
- **דירוג:** מילות מפתח (חינם). אם מוגדר `ANTHROPIC_API_KEY`, גם Claude מדרג את המשרות המבטיחות.

משתני סביבה: ראו `.env.example`.

## התראות Push למובייל

בדף **האיפיון שלי → התראות למכשיר** אפשר להפעיל או לכבות התראות לכל מכשיר בנפרד ולשלוח התראת בדיקה. ההתראות נשלחות בסיום הסריקות לפי סף ההתאמה שבאיפיון, לצד המייל, גם כשהאתר סגור. באייפון ובאייפד נדרש iOS 16.4 ומעלה: פותחים ב־Safari, בוחרים שיתוף → הוסף למסך הבית, ופותחים את joBot מהסמל כדי להפעיל התראות. באנדרואיד אפשר להפעיל בדפדפן תומך כגון Chrome. נדרש HTTPS (או localhost בפיתוח).

הגדרה ראשונית:

1. `npm run push:keys` שומר זוג מפתחות חדש ב־`.env.local` בלי להדפיס את המפתח הפרטי. לא להחליף מפתחות קיימים: החלפה מחייבת הרשמה מחדש של המכשירים.
2. להגדיר `VAPID_SUBJECT` עם כתובת קשר אמיתית, למשל `mailto:your-address@example.com`.
3. להעתיק **את אותם שלושת הערכים** (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`) למשתני הסביבה של האתר ול־GitHub Actions secrets. המפתח הפרטי נשאר בשרת; האתר מעביר למכשיר רק את המפתח הציבורי.
4. פריסת production ב־Vercel מחילה את המיגרציות אוטומטית לפני הבנייה. אם עדכון בסיס הנתונים נכשל, הפריסה נעצרת. לפיתוח מקומי אפשר להריץ `npm run db:migrate`; הסריקה גם מחילה את המיגרציות אוטומטית.
5. לפרוס מחדש, לפתוח מהטלפון, ללחוץ **הפעל התראות במכשיר הזה**, לאשר את בקשת ההרשאה וללחוץ **שלח התראת בדיקה**.

כל מכשיר מתחיל לקבל רק משרות שנמצאו אחרי ההרשמה; אין שליחת כל המאגר בפעם הראשונה. אם דירוג AI מופעל, המשרות נשלחות רק אחרי דירוג AI, כמו במייל. מעקב השליחה נשמר בנפרד לכל מכשיר; כשל במכשיר אחד אינו מסמן משרות כנשלחות במכשיר אחר או במייל. הרשמות שפגו נמחקות אוטומטית. כשל זמני נבדק שוב בסריקה הבאה, כל עוד המשרה חדשה ובחלון של שבעה ימים. אישור של ספק ה־Push אינו מבטיח שהמערכת בטלפון הציגה התראה; אפשר לבדוק הרשאות ומצב שקט במכשיר. במקרה נדיר שבו השליחה הצליחה ושמירת האישור למסד הנתונים נכשלה, ייתכן ניסיון חוזר.

לסריקה ידנית בלי התראות: `npm run scrape -- --no-email --no-push`. האפשרות `--no-email` לבדה מכבה רק מייל. ריצת `--dry` אינה שולחת התראות.
